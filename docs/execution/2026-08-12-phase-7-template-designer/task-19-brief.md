## Deliverable

1. **`POST /api/templates/[id]/preview`** — the side-effect-free render:
   - Body: the **in-editor config** (the working/unsaved `TemplateConfig`, validated with `validateConfig` — a preview of an over-budget/invalid config 400s the same as a save, no render) + the **picked record id** (docType-appropriate) + any preview params (statement's `asOf`/`combineFamily`).
   - Gate: `requireUser` + `mustCan(templates, "view")` **PLUS the record's own print-route permission** — `orders.view` (traveler), `shipping.view` (ticket/BOL), `certs.view` (cert), `invoicing.view` (invoice/credit), `receivables.view` (statement), `quotes.view` (quote). A preview exposes the real record's amounts, so it must never be a cheaper read than the print itself (§5.5). Route-test the pairing (a user with `templates.view` but not the record's area is 403).
   - Renders: read the picked record's data on the request's tx (the SAME reads the print path uses — reuse `readXPdfData`), build via `buildXDefinition(data, config)` with the **submitted config** (not the resolved/published one — this is a preview of the draft), embed the logo from the draft version's stored bytes when present, `renderPdf`, stream the bytes. **NO `storeDocument`, NO `templateVersionId` stamp, NO `printedAt` write, NO number allocation.** The statement preview forces finance-charge assessment OFF (the write path — Task 13's rule) and takes `asOf`/`combineFamily` (defaults today/false).
   - A preview must be renderable even for a DRAFT that has never published (it renders the submitted config directly — it does NOT go through `resolveTemplateForPrint`, which requires a published version).
2. **The preview pane in the editor** (`TemplateEditor.tsx` / a `PreviewPane` component): a per-docType **record picker** (reuse the house search components — order picker for traveler, shipment for ticket/BOL [MOS↔multi-order / SHIPPER↔single filter], cert, invoice **or credit** for INVOICE [a credit exercises the negative-format knob], customer for statement, quote) and a rendered-PDF view (embed the streamed bytes — an `<iframe>`/`<embed>` of the PDF blob, or an image, your call; it must show the WORKING config so edits reflect on re-preview). Preview is a read — available on `templates.view`; the record picker only offers records the user can view.
3. **Side-effect-free is the load-bearing invariant** — assert it: a preview writes NO `StoredDocument`, does not set `printedAt`, does not assess finance charges, does not bump the draft's `updatedAt`. Test each.
